# arXiv Digest v0.3.0

Version 0.3.0 is the manual-bootstrap release for one-click updates.
It retains application-data generation 2 and the existing reading workflow.

## Highlights

- Later compatible releases can offer **Update and restart** without a second
  confirmation. The new dashboard reports the verified final outcome.
- Preparation verifies the release wheel, snapshots the complete environment,
  creates a private data backup, and finishes admitted background work before
  shutdown. Package installation and recovery are offline.
- Browser tabs distinguish temporary preparation from restart handoff and use
  bounded, nonsecret transition markers to restore old-tab guidance.
- Update notices cover the full discovery deadline and keep manual instructions
  for unsupported installations or inconclusive checks.
- Dashboard commands support `--copy-url`, including Windows clipboard/browser
  helpers when running under WSL.
- Similarity explanations link to the matching seed or saved paper. Library
  cards include arXiv links and clarify how saved papers and searches are ordered.
- `doctor` reports pending or blocked update recovery without starting recovery,
  opening application data, or exposing local recovery paths.

## Install or upgrade

Versions 0.2.0 and 0.2.1 require a manual upgrade. The published tag must exist
before these commands can be used. For an existing pipx installation, select
**Quit**, wait for the app to stop, and run these commands one at a time from
a private folder:

```bash
arxiv-digest export arxiv-digest-before-0.3.0.zip
pipx install --force git+https://github.com/yuzhangmath/arxiv-digest.git@v0.3.0
arxiv-digest doctor
arxiv-digest
```

Continue only after the export succeeds; choose a new backup filename if it
already exists. Confirm that `doctor` reports `arXiv Digest 0.3.0`, then check
your interests, Library, review progress, and PDF folder in the reopened app.
If you use the desktop launcher, quit and run `arxiv-digest install-launcher`
to refresh it. See the [complete upgrade guide](../installation.md#upgrade-within-application-data-generation-2)
for installation detection, virtual environments, and troubleshooting.

For a fresh installation, follow [Install arXiv Digest](../installation.md#install-arxiv-digest),
then run `arxiv-digest init`; the backup and upgrade steps above are for existing users.
There is no profile reset or backup import for a generation-2 upgrade.
Downloaded PDFs remain in their chosen folder and are not included in the
backup. Users of 0.1.x must instead follow
[Clean reset with recovery copy](../installation.md#clean-reset-with-recovery-copy).

## Automatic-update support

The 0.3.0 manifest deliberately disables automatic installation from earlier
clients. A verified 0.3.0 installation can later update to an eligible release.
Initial support requires macOS/Linux, pipx exactly 1.16.7 with its `pip` backend,
an unsuffixed per-user environment, the retained interpreter, no injected or
system-site packages, completed setup, and unchanged runtime requirements.
The installed source must be the canonical tag or a prior protected updater
installation with its retained verified wheel.

Unsupported layouts, dependency-changing releases, absent manifests, or
unverified provenance keep the manual link. No installation metadata is
rewritten merely to make eligibility pass.

## Recovery and privacy

The complete verified environment snapshot is the package rollback source.
Private portable backups protect application data; if a failed target opened
it, recovery first preserves a raw copy of the current bytes. Downloaded PDFs
are not rolled back. Pending or ambiguous recovery state refuses to overwrite
an unexpected installation.

A safe preparation failure restores normal use and ordinary bounded sync.
Canceled PDF and candidate-corpus jobs require manual retry. If restart does
not produce a new tab after a few minutes, reopen arXiv Digest. For a guarded
failure, fully quit and follow the
[fixed recovery instructions](../troubleshooting.md#an-update-or-restart-did-not-finish).
Do not remove journals, snapshots, wheels, or lock files to bypass recovery.

GitHub receives public release-list, manifest, and chosen wheel-download
requests, including ordinary connection details and the application's
User-Agent. Interests and Library contents are not sent. Keep local recovery
plans, backups, environment snapshots, raw copies, and diagnostic logs private.
Receipts live only in the atomic journal and are acknowledged after display.

## Compatibility and limitations

The supported native platforms are macOS and Linux; Windows is not supported.
For installation or recovery problems, see [Troubleshooting](../troubleshooting.md).

This is not a scheduler, login service, telemetry service, or cloud account.
ArXiv requests are still needed for setup, synchronization, paper lookup, and
PDF download. The application does not cryptographically encrypt local data.
For diagnostic feedback, follow [Run redacted diagnostics](../troubleshooting.md#run-redacted-diagnostics).
Do not share personal
profiles, databases, backups, PDFs, logs, local recovery paths, or session URLs.
